A real run

Ask for a print in a sentence.

The agent picks the right tools, runs the real slicer on your computer and comes back with numbers and pictures you can check.

Previews

See every layer before the nozzle heats up.

The first layer

Check the first layer's walls and fill before anything else. Most failed prints start here. preview_gcode draws any layer coloured by feature.

Any layer, up close

Pick layer 12 or layer 40. Outer walls, inner walls, infill, bridges and supports each get their own colour, so a thin wall or a missing bridge is easy to spot.

The whole part at once

Every layer stacked and shaded by height. Lighter means higher. It's the quickest way to confirm the part sits where you expect on the bed.

From the side

A front elevation of the print, so overhangs and supports show up at a glance.

Watch it build

animate_layers saves a GIF of the print going up layer by layer. print_card makes a 1200×630 summary you can drop into a chat or an order.

Beyond slicing

The jobs that used to eat your evening.

Profiles, failed prints, weak parts and wasted filament. Hand them to the agent and it does the fiddly part with the slicer you already use.

Snap the spool label. Get a filament profile.

Send a photo of the label. The agent reads the brand, material, colour and temperature ranges, and create_filament_profile builds a preset from them, starting from the closest one your printer already has. You see a preview first and nothing is saved until you say so. Anything the label doesn't say gets a typical value for that material, and the agent tells you which ones.

name      Example PETG Galaxy Black

nozzle    240 °C, first layer 245 °C
bed       75 °C
colour    #1B1B1F
density   1.27 g/cm³
saved     not yet (preview)

The preview for a PETG label that reads 230 to 250 °C nozzle and 70 to 80 °C bed. Spools also go into a small inventory on your computer, so later the agent can tell you which one has enough left for a print.

Show it the failed print.

Stringing, warping, split layers, a messy first layer. The agent looks at your photos and matches them to one of 13 known defects. diagnose_print then suggests setting changes based on the presets you actually used. When two fixes pull in opposite directions, it says so and leaves that setting alone.

diagnose_print

Make it stronger on purpose.

Say how the part gets loaded: pulled, pushed, bent, hit or twisted, and in which direction. analyze_strength finds thin waists in the shape, then suggests an orientation plus walls, infill and layer height. find_best_orientation ranks ways to lay it on the bed for less support, speed, strength or adhesion.

analyze_strengthfind_best_orientation

Less purge, more print.

Every colour change on a single-nozzle printer flushes filament. In a two-colour test on a Kobra X, 12.37 g of a 25.07 g print went to colour changes. optimize_multicolor measures that waste for your model, tries settings that might reduce it and recommends one only if every colour survives and it really saves filament. It also suggests layout changes, like fewer colour switches per layer.

Reference

All 23 tools.

Your agent sees these with full descriptions. You never need to call them yourself, but it helps to know what's there.

Slice

Finds Anycubic Slicer Next and reports the printer, process and filament selected in the app.

Lists printer, process and filament presets, filtered to the ones made for your printer.

Shows a preset's settings with inheritance resolved, or searches for a setting name.

Size, volume, triangle count, watertight check and build-volume fit for STL, OBJ, 3MF or STEP.

Slices to G-code and a .gcode.3mf with any setting overrides, rotation, scale, copies and multi-colour.

Local and careful

Your printer stays yours.

It never prints.

The server writes G-code and .gcode.3mf files on your computer. Sending them to the printer is always your call.

Runs on your machine.

It drives the slicer's own command line. Models, presets and spool records stay on your computer.

Refuses risky files.

Project files that carry post-processing scripts are rejected, since those scripts can run programs. Custom G-code templates are off limits unless you turn them on.

Install

Two ways to set it up.

Hand a prompt to your agent, or follow four steps yourself.

Prompt for your agent

Paste this into Claude Code, Cursor, Codex, Antigravity or another coding agent.


    


    
    
      
  1. Install Anycubic Slicer Next
    Get it from Anycubic, then open it once and pick your printer so it sets up its presets.
    2. 
      
  2. Install uv
    uv installs Python tools in their own environment. Use the command for your system from the uv install page.
    3. 
      
  3. Install the server
    
        
    uv tool install --python 3.13 git+https://github.com/pri-te-sh/anycubic-slicer-mcp
    
        
    This puts an anycubic-slicer-mcp command on your PATH. uv tool dir --bin prints where it lives.
    4. 
      
  4. Add it to your AI app
    
        
    
          
          
          
          
          
          
        
    
        
    claude mcp add anycubic-slicer --scope user -- anycubic-slicer-mcp
    
        
    Settings › Developer › Edit Config, then add this to claude_desktop_config.json. Desktop apps often don't see your shell's PATH, so use the full path that uv tool dir --bin prints.
    
          
    {
  "mcpServers": {
    "anycubic-slicer": {
      "command": "/Users/you/.local/bin/anycubic-slicer-mcp"
    }
  }
}
    
        
    Add to ~/.cursor/mcp.json:
    
          
    {
  "mcpServers": {
    "anycubic-slicer": { "command": "anycubic-slicer-mcp" }
  }
}
    
        
    Add to .vscode/mcp.json in your workspace:
    
          
    {
  "servers": {
    "anycubic-slicer": { "type": "stdio", "command": "anycubic-slicer-mcp" }
  }
}
    
        
    codex mcp add anycubic-slicer -- anycubic-slicer-mcp
    
        
    Any MCP client works. Add a stdio server named anycubic-slicer whose command is anycubic-slicer-mcp (or its full path). In Antigravity, open the MCP servers panel, choose to edit the raw config and add the same mcpServers entry shown for Cursor.
    
        
    Then ask your agent to run slicer_status. It should name the printer you picked in the slicer.

Questions.

    

      
Does it send anything to my printer?
No. It slices on your computer and writes G-code and .gcode.3mf files. You send them to the printer yourself.

      
Which printers does it support?
Any printer that has a preset in Anycubic Slicer Next, because the server reads the slicer's own presets. It has been tested end to end on a Kobra X with a 0.4 mm nozzle. If you run it on another model, a printer report helps a lot.

      
Which AI apps can use it?
Anything that speaks the Model Context Protocol over stdio: Claude Code, Claude Desktop, Cursor, VS Code, Codex, Antigravity and others.

      
Do I need to keep the slicer window open?
No. The server runs the slicer from the command line in the background. It reads the printer, process and filament you last picked in the app, so open it once to choose them.

      
Does it work on Linux?
Not yet. It supports Windows and macOS. Pull requests for Linux are welcome.

      
My slicer is installed somewhere unusual.
Set ANYCUBIC_SLICER_EXE to the slicer program and, if needed, ANYCUBIC_SLICER_DATA to its data folder, in your MCP client's config for this server.

      
Is this made by Anycubic?
No. It's an independent open-source project under the MIT licence and isn't affiliated with or endorsed by Anycubic.
